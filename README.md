# atlas-infra

Infrastructure as code for Atlas, provisioned via Pull Request. Defines the local experimentation
cluster (kind), namespaces and service dependencies (e.g. PostgreSQL). It provisions resources only —
application deployment lives in `atlas-gitops` + Argo CD.

## Contents

- `kind-config.yaml` — declarative local cluster definition (host ports 80/443 mapped to
  ingress-nginx; node labelled `ingress-ready=true`).
- `bootstrap.sh` — provisions the platform layer in one command: kind cluster → Argo CD →
  ingress-nginx → root Application (app-of-apps). It does **not** provision the per-service
  resources: namespaces, the `ghcr-pull` secret and Postgres are owned by Terraform. After
  bootstrap, a `terraform apply` (via PR merge, or run manually) must run before a service can
  leave `OutOfSync`/`Missing` — the namespace it deploys into does not exist until Terraform
  creates it. Once both the platform and the service infra exist, each service is reachable at
  `http://<name>.127.0.0.1.nip.io` (ADR atlas-infra/0007, atlas-templates/0006).
- `services/` — Terraform root module. `main.tf` configures the providers; per-service files
  (`svc-<name>.tf`, generated by atlas-api via PR) call the reusable module.
- `modules/service/` — reusable module: a namespace; a `ghcr-pull` image pull secret (dockerconfigjson,
  so private GHCR images can be pulled); and, when enabled, a PostgreSQL instance. All secrets are
  generated/supplied at apply time and kept in tfstate — never committed.
- `.github/workflows/terraform.yml` — `terraform plan` on PRs, `terraform apply` on merge to main,
  on a **self-hosted runner** (a cloud runner cannot reach the local kind cluster).

### Required secrets (repository → Settings → Secrets)

- `GHCR_PULL_USERNAME` / `GHCR_PULL_TOKEN` — a username and a token with `read:packages`, used to build
  the `ghcr-pull` image pull secret in each service namespace. Passed to Terraform as
  `TF_VAR_ghcr_username` / `TF_VAR_ghcr_token`. Without them the pull secret is skipped and private
  images fail to pull.

## Provisioning flow

```
atlas-api → opens a PR adding services/svc-<name>.tf → human review + merge → runner: terraform apply → kind
```

The merge is the human gate; Terraform never runs before it.

### Terraform state

The `tfstate` is kept under `$HOME/atlas-tfstate/` on the runner — **outside** the Actions working
directory (`_work`). This is deliberate: `actions/checkout` cleans the workspace (`git clean -ffdx`)
on every run, which would delete a gitignored state file living next to the code and make Terraform
lose track of what it created (orphaned namespaces/databases). The path is supplied at `init` time via
`-backend-config` (see `.github/workflows/terraform.yml`), so no host-specific path is committed. The
state is local to the runner and never committed (it may contain secrets).

## Run

> Requires the Docker daemon running.

```bash
# Full environment from scratch (cluster + Argo CD + apps), idempotent:
./bootstrap.sh

# Or just the cluster:
kind create cluster --config kind-config.yaml
kind delete cluster --name atlas-local
```
